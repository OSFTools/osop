
# Contributing

Thank you for your interest in contributing to OSOP. The full contributor guidelines and development workflow live in the project documentation: see the Development guide at [docs/source/devel.md](docs/source/devel.md).

- Quick start checklist

- Create a feature branch from `main` (use prefixes like `feature/`, `bugfix/`, or `release/`).
- Add or update tests and documentation for any changes.
- Run `pre-commit` and `pytest .` locally before opening a pull request.
- Ensure CI checks pass and request at least one reviewer on your PR.

Pull request checklist

- Tests: new code is covered by tests and `pytest .` passes.
- Lint: run `pre-commit` and fix any issues.
- Description: PR body explains the rationale and links related issues.
- Review: assign reviewers and address review comments.

Policies and links

- Code of Conduct: Please follow our Code of Conduct (see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md)).
- Contributor Licence Agreement (CLA): this project uses a CLA; you may be prompted to sign it when opening your first PR. See the CLA assistant at https://cla-assistant.io/OSFTools/osop/.
- Release process: maintainers should follow the Release Process (see the Development guide `docs/source/devel.md`, or the short Release Process summary in the repository).

For full development instructions, environment setup, and the detailed release procedure, see the Development guide at [docs/source/devel.md](docs/source/devel.md).

If you'd like, open an issue or discussion describing your planned change before starting larger work so maintainers can provide early feedback.
